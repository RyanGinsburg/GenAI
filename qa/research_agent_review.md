**This is the most significant miss in the whole review.** The original run returned `not_found: true` for this club with everything null, but the live `/recruitment.html` page actually has real, concrete deadline/info-session/coffee-chat data — this club should have come back as a genuine hit, not a null result.

**Root cause found (2026-09-03), and it's not JS rendering as originally suspected:** fetched the raw static HTML directly (no browser, no JS execution) and the concrete timeline, dates, and coffee chat link are all present in it — `BeautifulSoup.get_text()` picks up all of it (814 characters total, nowhere near the 12000-char truncation limit). The actual cause is that the page's hero section has a stale placeholder line - "Recruitment details for the upcoming semester will be announced soon. Enter your email to be notified when applications open." - sitting directly above the real, filled-in timeline further down the same page (the club apparently never removed/updated that banner once they published real dates). Both pieces of text reach the model, and it appears to have let the vague "will be announced soon" banner override the concrete timeline below it rather than extracting the specific dates that are actually stated. **Fixed** by adding an explicit rule to `SYSTEM_PROMPT` in `research_agent.py`: a vague placeholder elsewhere on the page must not suppress a concrete date/time/link that is also present. Not yet re-run against the live Claude API to confirm the model now extracts it correctly (needs `ANTHROPIC_API_KEY` — try `python -m backend.services.research_agent https://www.cornell-wsc.com/recruitment.html`).

## Summary of findings (2026-09-03 review)

**19/20 sites re-checked live and confirmed reachable** (Black Ivy Pre-Law Society's domain has stopped resolving since the original run and couldn't be re-verified; Alpha Kappa Psi's domain was already dead and still is — both are pre-existing site issues, not bugs in the code).

**Two real problems with the extraction were found, and both are now fixed in `backend/services/research_agent.py` (2026-09-03):**

1. **Coffee chat links were being missed systematically — 6 of the 7 clubs that actually have one were missed:** Cornell Business Analytics Club, Cornell XR, 180 Degrees Consulting, Cornell FinTech Club, AppDev at Cornell (5 separate links!), and Investment Banking Club all had a real, live coffee-chat sign-up link (Google Form or Calendly) that came back `null`. Root cause: `_page_text()` called `soup.get_text()`, which strips out all `<a href>` URLs and keeps only the visible link text (e.g. "Sign Up Now", "☕ Coffee Chats ☕"). So even when a coffee chat link was right there on the page, Claude was never actually given the URL to extract. **Fixed:** `_page_text()` now appends each link's absolute URL in parentheses right after its anchor text (e.g. `Sign Up Now (https://forms.gle/QVANkxqyxctXZvFx7)`) before the text goes to the model, and `SYSTEM_PROMPT` now tells it to use that. Verified against the saved HTML for Cornell Wall Street Club, AppDev, and Cornell Business Analytics that the target URLs now appear in the extracted text — not yet re-run against the live Claude API (needs `ANTHROPIC_API_KEY`).

2. **Cornell Wall Street Club came back entirely `not_found: true` when it should have been a real hit.** Turned out not to be JS rendering (the raw static HTML has all the real data, well within the character limit) — the page has a stale "details will be announced soon" hero banner sitting above its real, filled-in timeline, and the model appears to have let that vague banner override the concrete dates below it. **Fixed:** added an explicit rule to `SYSTEM_PROMPT` that a vague placeholder elsewhere on the page must not suppress a concrete date/time/link that's also present. See the club's section above for the full root-cause trace. Also not yet re-run against the live API.

**Minor, also fixed:** for Blockchain at Cornell, the "secondary page" heuristic (`_find_secondary_url`) followed an off-domain LinkedIn profile URL instead of a real club page. `_find_secondary_url` now only returns links on the same domain as the page it's crawling.

**Everything else — all 4 fields on the other 16 clubs, and the 3 already-correct fields on the clubs above — checked out correct**, including the not_found cases (most club sites genuinely don't post this info, consistent with what CLAUDE.md already expected).

**Still to do:** re-run `qa/research_agent_review.py` against the live Claude API (needs a working `.env` with `ANTHROPIC_API_KEY`) to confirm the fixes actually change the model's output for these clubs, ideally focusing on Cornell Wall Street Club and a couple of the coffee-chat-link clubs before marking Step 4 fully done.
